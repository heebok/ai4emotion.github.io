Antenna Safety Simulator — Technical Engineering Guide

Stage 4B-1 · Naval and Aircraft RF Co-Site / Near-Field / LNA Safety Modeling

1. Purpose of This Guide

This document explains the physical principles, equations, computational approximations, and implementation choices used during development of the Antenna Safety Simulator. It is intentionally more detailed than the User Manual.

The simulator is designed for interactive engineering screening of RF coupling from one or more transmitters into a candidate receiver/LNA on simplified ship and aircraft platforms. The app combines:

  • electromagnetic field-region classification,
  • directional antenna gain,
  • Friis-style far-field transfer,
  • approximate Fresnel-region corrections,
  • reactive-near-field screening corrections,
  • polarization mismatch,
  • structural obstruction / knife-edge screening,
  • measured or simulated S21 override,
  • pulse duty-cycle averaging,
  • multiple-transmitter aggregation,
  • receiver/LNA damage-threshold logic,
  • 3D field-zone visualization,
  • aircraft curved-surface propagation,
  • creeping-wave approximation,
  • helicopter rotor shadowing and Rotor Blade Modulation (RBM),
  • worst-case rotor-angle search.

The user-supplied aircraft report motivated the Aircraft track's emphasis on co-site interference, near-field coupling, curved fuselage propagation, rotor shadowing, RBM, desensitization, and LNA protection. The report also makes clear that platform-specific material, antenna, and installation data are essential. Accordingly, several software coefficients are deliberately user-tunable rather than treated as universal constants.

2. Units and Coordinate Systems

The internal coordinate unit is meter. Frequency is stored in Hz. Power quantities use dBm. Gain/loss quantities use dB/dBi.

Naval

  • +X: Bow
  • +Y: Starboard
  • −Y: Port
  • +Z: upward / height

Aircraft

  • +X: Nose
  • +Y: Starboard
  • −Y: Port
  • +Z: Up

For an antenna boresight with azimuth φ and elevation θ, the unit vector is

b = (cos θ cos φ, cos θ sin φ, sin θ)

with angles converted to radians for numerical evaluation.

For two vectors a and b, the off-axis angle is

ψ = arccos[(a · b) / (|a||b|)]

3. Wavelength

The fundamental wavelength calculation is

λ = c / f

where

  • c = 299,792,458 m/s
  • f = transmitter frequency in Hz
  • λ = wavelength in meters

The transmitter frequency controls wavelength, free-space path loss, near/far-field boundaries, Fresnel phase curvature, and diffraction parameters.

4. Electromagnetic Field-Region Classification

Let D be the larger of the transmitter and receiver maximum linear antenna dimensions used for the link-region classifier.

For electrically large antennas (D ≥ λ/2), the implementation uses:

Reactive-near-field boundary:
R1 = 0.62 √(D³ / λ)

Far-field boundary:
RF = max(R1, 2D² / λ)

The regions are then

r ≤ R1            → Reactive Near Field
R1 < r < RF       → Radiating Near Field / Fresnel Region
r ≥ RF            → Far Field / Fraunhofer Region

For electrically small antennas (D < λ/2), the app uses the practical fallback:

R1 = λ / (2π)
RF = λ

This small-antenna fallback is an implementation choice designed to avoid meaningless zero/tiny aperture boundaries when a compact monopole/dipole dimension is entered.

Field-Zone Visualization

For each transmitter alone, the 3D visualization computes field boundaries using the transmitter dimension. The shell represents the theoretical region boundary. The fog is only a visual aid and may be mildly directionally shaped; it does not redefine the theoretical radius.

5. Baseline Far-Field Transfer

For direct spatial modeling, the simulator begins from a Friis-like link budget.

Free-space path loss:

FSPL = 20 log10(4πr / λ)

The baseline peak receiver input is

Pr,peak = Pt
        + Gt,eff
        + Gr,eff
        - FSPL
        - Lpol
        + Cregion
        - Lobstruction
        - Lfilter
        - Lcable
        - Llimiter

where:

  • Pt: transmitter power at the antenna reference plane [dBm]
  • Gt,eff: effective TX directional gain [dBi]
  • Gr,eff: effective RX directional gain [dBi]
  • Lpol: polarization mismatch loss [dB]
  • Cregion: near/Fresnel correction [dB]
  • Lobstruction: structural / surface propagation loss [dB]
  • Lfilter: frequency-dependent receiver rejection [dB]
  • Lcable: receiver path cable loss [dB]
  • Llimiter: receiver limiter loss [dB]

The model is a screening formulation. In particular, classic Friis assumptions do not rigorously hold in the reactive near field; the app therefore either applies a screening correction or allows S21 to override the spatial model.

6. Measured / Simulated S21 Override

If the transmitter includes a measured or trusted simulated S21 value, the software bypasses the spatial propagation estimate for that link:

Pr,peak = Pt + S21 - Lfilter - Lcable - Llimiter

S21 is expected in dB and is normally negative for passive coupling/isolation.

This is the preferred workflow for tightly coupled reactive-near-field installations when validated data exist, because a measured/full-wave S21 inherently contains coupling behavior that a simplified Friis-like screening equation cannot reproduce.

7. Analytic Antenna Pattern

When no pattern CSV is loaded, the app uses the simple analytic attenuation law

A(ψ) = min[Amax, 12(ψ / HPBW)²]
Geff(ψ) = Gpeak - A(ψ)

where:

  • ψ is the off-axis angle,
  • HPBW is the entered half-power beamwidth parameter used by the app,
  • Amax is the maximum off-axis attenuation.

This is a smooth engineering approximation, not a universal antenna pattern.

1D imported pattern

A 1D pattern provides gain vs off-axis angle. The implementation sorts points by angle and performs linear interpolation.

2D imported pattern

A 2D pattern provides (azimuth offset, elevation offset, gain). The current implementation selects the nearest supplied 2D sample. Therefore, dense sampling is recommended for 2D CSV data.

8. Polarization Loss

The current implementation uses the following practical rules:

  • same linear polarization: 0 dB
  • vertical vs horizontal: 60 dB numerical isolation proxy
  • same circular handedness: 0 dB
  • RHCP vs LHCP: 60 dB numerical isolation proxy
  • linear vs circular: 3.0103 dB
  • unknown polarization: 0 dB

The 60 dB value is a finite software proxy for a theoretically deep orthogonal-polarization null. Real installed platforms rarely achieve ideal orthogonality because of scattering, structural currents, antenna imperfections, and multipath. Critical studies should replace this simplification with measured/certified isolation or S21.

9. Fresnel / Radiating-Near-Field Models

The simulator provides four choices.

9.1 Numerical Aperture Integral

For a circular aperture of diameter D, a grid is generated over the aperture. For each aperture sample i, the exact distance to the target is ri.

The near-field complex sum is approximated by

HNF ≈ Σ exp(-j k ri) / ri

where

k = 2π / λ

A corresponding far-field reference sum is formed from the projected aperture phase:

HFF ≈ Σ exp(j k Δri·r̂) / R

The correction is

C = 10 log10(|HNF|² / |HFF|²)

The implementation clamps the result to a practical numerical range to avoid singular/extreme values during interactive use.

For the full link, TX and RX aperture corrections are added.

9.2 Raw Gamma Approximation

The implementation uses

γraw = 1 - exp[-α r λ / D²]

with

α = 0.06

This α is an empirical implementation constant, not a universal electromagnetic constant.

9.3 Smooth Gamma

The raw gamma is normalized at the far-field boundary:

γsmooth(r) = γraw(r) / γraw(RF)

clamped to a stable numerical interval.

The TX and RX factors are multiplied and converted to dB:

Cregion = 10 log10(γTX γRX)

9.4 No Fresnel Correction

Keeps the Friis-like baseline without a Fresnel correction.

Heat-map optimization

When the expensive numerical aperture model is selected, dense heat-map calculations may automatically use the fast smooth-gamma path to preserve interactivity.

10. Reactive-Near-Field Screening Correction

The reactive region is not rigorously described by Friis transfer. The simulator therefore uses antenna-type-dependent screening factors.

Let

k = 2π / λ
x = kr

Dipole / Monopole

The software forms

F = √[(1 - 1/x²)² + (1/x)²]
Creactive = 20 log10(max(1, F))

Small Loop

F = √[1 + 1/x² + 1/x⁴]
Creactive = 20 log10(max(1, F))

Generic Aperture

F = max[1, (R1/r)²]
Creactive = 20 log10(F)

The correction is capped for numerical robustness. These formulas are best treated as screening indicators. In a real reactive-near-field installation, measured or validated full-wave S21 should take precedence.

11. Receiver Filter and Front-End Losses

The link-specific rejection is

Lfilter = max[0, Lmanual + Lcurve(f)]

where Lcurve(f) is interpolated from the imported receiver filter-response CSV.

Additional receiver-path terms are then subtracted:

Ltotal_frontend = Lfilter + Lcable + Llimiter

The user must ensure the reference plane is consistent. For example, if TX power is specified after feeder loss, do not subtract that feeder loss a second time elsewhere.

12. Pulse Waveform and Average Power

For pulse transmission:

Duty = PRF × PulseWidth × 10⁻⁶

with pulse width entered in microseconds.

The implementation clamps Duty to [10⁻⁹, 1].

Average power is

Pr,avg = Pr,peak + 10 log10(Duty)

For CW:

Duty = 1
Pr,avg = Pr,peak

Peak and average risk are evaluated independently because a receiver may have different pulse and CW damage tolerances.

13. Risk and LNA Safety Logic

Let

Pallow,pulse = Pdamage,pulse - Msafety
Pallow,CW    = Pdamage,CW    - Msafety

The software evaluates:

RiskIndex_peak = Pr,peak - Pallow,pulse
RiskIndex_avg  = Pr,avg  - Pallow,CW

Risk classification for each basis:

Pr ≥ Pdamage                         → CRITICAL
Pallow ≤ Pr < Pdamage                → HAZARD
Pallow - WarningBand ≤ Pr < Pallow  → WARNING
Pr < Pallow - WarningBand           → SAFE

The more severe of peak and average classifications becomes the displayed basis.

The thresholds are user inputs. The app does not assume that every GaAs, SiGe, CMOS, BiCMOS, or GaN LNA has a common damage rating.

14. Multiple-Transmitter Aggregation

14.1 Incoherent Power Sum

Each dBm value is converted to watts:

Pi(W) = 10^[(Pi,dBm - 30)/10]

Then

Ptotal(W) = Σ Pi(W)
Ptotal,dBm = 10 log10(Ptotal) + 30

14.2 Worst-Case Coherent-by-Frequency Mode

Transmitters are grouped if their frequencies lie within the configured tolerance. Within a group, the simulator sums square-root power amplitudes conservatively:

Agroup = Σ √Pi
Pgroup = Agroup²

Different frequency groups are then summed in power.

This is a conservative envelope, not a phase-synchronized waveform simulation.

15. Naval Structural Obstruction and Knife-Edge Screening

The Naval geometry engine tests the TX→RX segment against simplified axis-aligned 3D boxes representing masts, bridge blocks, and other structures.

For an intersected structure, the software estimates clearance h above the ray and forms the Fresnel knife-edge parameter

ν = h √[ 2(d1 + d2) / (λ d1 d2) ]

The standard smooth knife-edge approximation used in the code is

LKE = 0                                           for ν ≤ -0.78
LKE = 6.9 + 20 log10( √[(ν - 0.1)² + 1] + ν - 0.1 )  otherwise

For multiple blockers, the strongest blocker is retained and an optional additional-blocker penalty is added. The total is capped for numerical/engineering stability.

A Fixed Block Loss mode and a Disabled mode are also available.

16. Aircraft Curved Fuselage Geometry

The aircraft fuselage is represented as a longitudinally tapered ellipse. At a given X position, local semi-axes are

ry(x) = 0.5 × FuselageWidth × Scale(x)
rz(x) = 0.5 × FuselageHeight × Scale(x)

The local implicit fuselage equation is

y²/ry² + z²/rz² - 1 = 0

A negative value indicates a point inside the fuselage.

Direct-path blockage

The TX→RX segment is sampled at multiple interior points. If samples penetrate sufficiently inside the fuselage, the direct path is marked blocked.

Surface ray picking

For SURFACE RX mode, the camera ray is sampled until it crosses from outside to inside the implicit fuselage. A binary refinement finds the skin intersection. Wing and tail surfaces are also tested as planar/polygonal surfaces.

This creates visually intuitive surface placement without requiring a CAD mesh or GPU ray-tracing library.

17. Aircraft Creeping-Wave Approximation

The user-supplied report discusses curved-fuselage surface creeping waves and gives a qualitative UTD-style form. The simulator uses the corresponding engineering structure rather than claiming a full UTD solution.

A representative form is

E(s) ∝ 1/√s × exp[-αcw (k/a²)^(1/3) s]

where:

  • s = surface path length
  • a = representative local curvature radius
  • k = 2π/λ
  • αcw = empirical coefficient

Geodesic-like path

The software projects TX and RX access points onto the elliptical fuselage. It computes angular separation around an equivalent ellipse and combines the circumferential arc with longitudinal separation.

The surface route length is approximated by

Scurved = √(Δx² + (aeq Δθ)²)
Ssurface = Saccess,TX + Scurved + Saccess,RX

with an equivalent radius based on the local ellipse.

Path-length penalty

Lpath = 20 log10(max[1, Ssurface / Sdirect])

Empirical curvature attenuation

The implementation forms an attenuation exponent in nepers:

N = αcw (k/a²)^(1/3) Ssurface

and converts to dB:

Lempirical = 8.686 N + Lfixed_surface

Total surface loss:

Lsurface = min[Lmax, Lpath + Lempirical]

The default αcw = 0 is intentional and conservative. The supplied report does not provide a universal coefficient valid for all aircraft materials, frequencies, coatings, panel joints, and antenna types.

18. Aircraft Surface Heat Map

A regular X–Y sampling grid is constructed over the aircraft planform. Candidate points are accepted if they lie on:

  • fuselage,
  • main wing,
  • tailplane.

For fuselage locations, both upper and lower surface points may be evaluated.

At each candidate RX point:

  1. every transmitter link is recalculated,
  2. curved-fuselage / creeping-wave logic is applied,
  3. rotor dynamics are applied for helicopter mode when enabled,
  4. multiple transmitters are aggregated,
  5. the resulting risk class is assigned to the surface cell.

The result is rendered directly on the 3D aircraft skin.

19. Near-Field Shell and Fog Rendering

The theoretical shell uses the same region-boundary equations as the RF classifier.

Visual fog may include:

  • modest radiation-pattern weighting,
  • obstruction-aware shaping,
  • animated opacity,
  • quality-dependent slice density.

Important distinction:

Theoretical Shell = electromagnetic region boundary estimate
Visual Fog        = intuitive spatial visualization aid
Damage Zone       = separate receiver/LNA power-risk calculation

These concepts should not be conflated.

20. Helicopter Tandem-Rotor Geometry

The Stage 4B generic Chinook-class template uses two tandem rotor discs. The public aircraft scale is used as a visual/engineering reference, while exact operational antenna locations are not reproduced.

Each rotor has:

  • center position,
  • radius,
  • blade count,
  • RPM,
  • rotation direction,
  • phase offset,
  • hub radius.

The forward and aft rotors rotate in opposite directions in the generic model.

21. Blade Passing Frequency

For a rotor with Nb blades and rotational speed RPM:

frotor = RPM / 60
fBPF   = Nb × RPM / 60

For example, a three-blade rotor at 225 RPM has:

frotor = 3.75 Hz
fBPF   = 11.25 Hz

RPM remains editable because actual operating speed and test condition must come from validated platform data.

22. Rotor-Disc Intersection

The rotor disc is modeled as a horizontal plane at the rotor center Z.

For TX point p0 and RX point p1, the line is

p(t) = p0 + t(p1 - p0),  0 ≤ t ≤ 1

The intersection with rotor plane z = zr is obtained from

t = (zr - z0) / (z1 - z0)

The radial distance from rotor center is

ρ = √[(x - xr)² + (y - yr)²]

The path crosses the active rotor annulus if

Rhub ≤ ρ ≤ Rrotor

23. Blade Angular Overlap and Shadowing

At the disc intersection, the azimuth is

φlink = atan2(y - yr, x - xr)

For each blade, the software computes the minimum angular difference between φlink and the instantaneous blade azimuth.

Let the user-defined full blade angular width be Wb. With half-width Wb/2, a soft overlap factor is

O = clamp[1 - Δφ/(Wb/2), 0, 1]

A radial weighting increases the effect toward the outer active blade span. The resulting shadowing loss is

Lshadow = Lshadow,max × Oweighted

This is a geometric engineering model; it does not solve scattering from a real composite/metal blade.

24. Rotor Blade Modulation (RBM)

The report describes periodic amplitude/phase/polarization and impedance variation as rotor blades move near or through antenna fields. The simulator represents this with a tunable periodic isolation term.

A simplified software form is

ΔIRBM = ARBM cos(Nb θr + δ) × Wgeometry

where:

  • ARBM = user-entered isolation swing [dB]
  • Nb = blade count
  • θr = instantaneous rotor phase
  • δ = geometry/rotor phase offset
  • Wgeometry = rotor-disc/proximity weighting

The sign changes with phase. A negative isolation delta means less isolation and therefore higher receiver input — the safety-worst direction.

The total dynamic additional link loss is

Ldynamic = Lshadow + ΔIRBM

and the adjusted link is obtained from the base aircraft link by subtracting this signed quantity from receiver input.

25. Effective Terminal Isolation

For reporting, the simulator defines

Ieffective = Pt - Pr,peak

This is called effective terminal isolation because it may include antenna gains, propagation, filters, cable/limiter terms, surface effects, and rotor dynamics. It is not necessarily the same reference-plane definition as a two-port antenna-to-antenna S21 measurement.

Reference planes must therefore be documented when comparing software values to measured isolation.

26. Worst-Case Rotor Scan

The master rotor phase is sampled from 0° to 360° over N points:

θi = 360° i / N,  i = 0 ... N-1

At each phase:

  1. base aircraft propagation is retained,
  2. each transmitter receives rotor shadow/RBM adjustment,
  3. all adjusted links are aggregated,
  4. peak and average risks are evaluated.

The worst overall phase is the phase maximizing the overall risk index.

Per transmitter, the software records the phase giving the maximum peak receiver input, which corresponds to the minimum effective isolation for that modeled installation.

Increasing N improves angular resolution at the cost of compute time.

28. Individual Transmitter JSON and Transmitter-Set JSON

An individual TX profile uses a transmitter object containing one complete AntennaSpec. A transmitter-set profile stores the full transmitters array. These formats support reuse of commercial, mission, or user-characterized antennas without forcing aircraft geometry to change.

29. Complete Aircraft Project JSON

A complete Aircraft Project stores:

  • projectName
  • AircraftPlatform
  • ReceiverSpec
  • transmitter array
  • RfEngineSettings
  • FieldZoneSettings
  • AircraftPropagationSettings
  • HelicopterRotorSettings when applicable
  • rotor phase when applicable

This is the preferred format for preserving an entire engineering study state.

30. Responsive UI and Android Tablets

The Flutter UI uses width-driven LayoutBuilder decisions rather than an iPad-only code path.

Examples:

Platform selector: wide-card layout when enough width is available
Aircraft planner:   side-by-side 3D + panel when maxWidth ≥ configured threshold
Phone:              stacked visualization + panel

Therefore a large Android tablet window will generally behave like an iPad/desktop wide window.

Nevertheless, Android tablet validation is still required because of:

  • different aspect ratios,
  • portrait/landscape dimensions,
  • Android navigation bars,
  • display cutouts,
  • system font scaling,
  • multi-window / split-screen,
  • foldable window resizing.

A responsive app should be tested against window size, not simply device type.

31. Source-Derived Principles vs Implementation Assumptions

Principles supported by the supplied aircraft report

The report supports the importance of:

  • co-site interference on aircraft,
  • near-field coupling,
  • reactive / radiating / far-field classification,
  • fuselage curvature and surface propagation,
  • rotor shadowing,
  • Rotor Blade Modulation,
  • time-varying isolation,
  • desensitization / gain compression,
  • LNA burnout risk,
  • worst-case rotor-angle consideration,
  • mitigation by filtering, limiting, blanking, cancellation, and separation.

Implementation assumptions introduced by the app

The following are practical software approximations rather than universal constants from the report:

  • smooth-gamma α = 0.06,
  • generic reactive-near-field correction functions,
  • 60 dB orthogonal-polarization numerical proxy,
  • box-based Naval obstruction geometry,
  • simplified aircraft tapered ellipse,
  • geodesic-like rather than full UTD creeping path,
  • user-tunable creeping αcw,
  • user-tunable rotor shadowing loss,
  • user-tunable RBM isolation swing,
  • simplified rotor-disc/blade angular overlap.

These distinctions are important for traceability and responsible engineering use.

32. Equations Mentioned in the Source but Not Used as Active Core Equations

The supplied report includes additional formulas and empirical relationships, including example horizontal/vertical antenna isolation expressions, phased-array far-field extensions, and device-technology examples. They are not automatically hardcoded into the current RF power engine unless explicitly described above.

This is intentional. Platform-specific empirical formulas should not silently replace the common RF engine without validated applicability to the user's actual installation.

33. Verification Hierarchy

For critical installation decisions, use the following hierarchy:

  1. Installed measurement / S-parameter test at documented reference planes.
  2. Validated full-wave EM analysis with realistic aircraft/ship geometry, materials, radomes, cables, and antenna ports.
  3. Platform-specific qualification data and manufacturer component limits.
  4. Antenna Safety Simulator for screening, comparison, visualization, what-if studies, and identifying cases that require more rigorous analysis.

The simulator is most valuable as an interactive engineering decision-support layer around these higher-fidelity sources.
